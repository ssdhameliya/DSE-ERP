DSE ERP 7.3.11

Included updates:
1. Sales and Purchase delete now retain the record and mark document status as DELETED.
2. Purchase delete no longer hard-deletes rows; stock is reversed once and audit history is preserved.
3. Legacy cancel flows map to soft delete for backward compatibility.
4. Sales and Purchase action menus expose Delete only; Cancel is removed from the UI.
5. Deleted documents remain visible in registers with DELETED status and are excluded from active financial totals.
6. Document / WhatsApp / payment-due status presentation continues through the shared semantic colour system.
7. Expanded shared IconFactory coverage for field labels, dialogs, dashboard panels, reports, settings and import fields.
8. Data Import field semantics and template version updated for 7.3.11.
9. Managed PostgreSQL startup recovery hardened: a stopped managed server is restarted automatically; an unready server is given time to recover and, if necessary, is safely stopped and restarted without recreating the existing database.
10. A proven-stale postmaster.pid can be removed only when pg_ctl, the OS process table and the configured port all confirm no live PostgreSQL server.
11. PostgreSQL readiness is verified with pg_isready before role/database verification and Spring Boot startup continue.
12. Update/rollback shutdown now verifies the postmaster PID, captured PostgreSQL child processes, runtime postgres.exe processes and the configured port are all released before an installer is allowed to start.
13. Windows update helper now independently checks that no postgres.exe from the bundled DSE ERP runtime remains before installation.
14. Windows update helper no longer relaunches a failed installer interactively; file-lock/update failures fail closed.
15. After a Windows update, required PostgreSQL executables/DLLs and absence of *.rbf artifacts are verified before DSE ERP is restarted.
16. Core application/runtime version strings are 7.3.11.

Safety rule: existing PostgreSQL data, runtime credentials and managed-instance identity are never regenerated by the startup recovery path.

Verification note: targeted Java syntax verification for the PostgreSQL runtime and Windows update launcher passed in the preparation environment. A full Maven/Java 25 build must still be run in the normal DSE ERP build environment.
11. Fixed IntelliJ/development resource loading: FXML, CSS, app metadata and bundled assets now resolve from the normal classpath first and safely fall back to Maven resource folders when IntelliJ has not marked src/main/resources on the runtime classpath. This fixes the Splash.fxml "Location is not set" startup failure without affecting packaged EXE/DMG resource loading.
