DSE ERP 2.1.5 - macOS Dialog Ownership Stabilization

Merged with Phase 1 Shared UI Framework.

Root cause:
Native JavaFX Alert/Dialog/TextInputDialog/ChoiceDialog objects were often created without initOwner() before show/showAndWait(). macOS therefore treated them as independent windows.

Correction:
- Added DialogOwnerResolver.
- Added OwnedAlert, OwnedDialog, OwnedTextInputDialog and OwnedChoiceDialog.
- Migrated native dialog construction paths to owner-aware classes.
- Dialogs use WINDOW_MODAL when the ERP stage exists.
- Startup-only dialogs fall back to APPLICATION_MODAL.
- Current theme and responsive classes are applied when shown.
- Existing Add/Edit and notification stage behavior is preserved.
- Phase 1 Shared UI Framework remains included.
- Project version remains 2.1.5.
